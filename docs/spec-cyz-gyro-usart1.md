# OPS9_fix 接管 QMM01/CY-Z 陀螺仪（USART1）：角度/角速度并入上报数据

> 本文档是 GitHub issue **#1** 的离线副本，便于随仓库查阅。
> **以 issue 为准**：https://github.com/Nyar-ai/OPS9_fix/issues/1
> 协议依据：本目录 `CY-Z协议.md`（2026-09-11 版），规则见 `README.md`。

## Problem Statement

OPS9_fix（STM32F103C8T6）目前只能靠两路外部计数（TIM1_CH1=PA8、TIM2_CH1=PA0）间接感知步进脉冲，用零位引脚（PB14/PB15）与方向引脚（PA10/PA11）判断零位与方向，**没有任何绝对航向参考**。机器人主控因此在断电重启或丢步后无法知道装置的绝对朝向，每次上电都必须重新找零，且找零失败时主控无从察觉。

厂商 QMM01/CY-Z 陀螺仪模块能提供积分角度（度）与零速冻结角速度（度/秒），厂商示例包（位于本工程目录之外，仅作只读参考）提供协议逻辑参考。但该示例是**按另一个工程的假设写的**：它把模块串口写死为主控链路要用的 USART2，还会与主控链路**抢占同一个 HAL 串口句柄**；它同时带一个面向调试串口的 printf 重定向，引用了一个本工程不存在的串口句柄，**原样搬进来会直接编译失败**。因此本工程**不复制、也不修改厂商源文件**，只把它当作协议行为的参考实现，在本仓库内自行实现协议层与访问层。

## Solution

以本工程 CubeMX 生成为基准，**在本仓库内自行实现**接入 QMM01/CY-Z 陀螺仪的协议层与访问层（厂商源文件零复制、零修改），把模块接进 **USART1**（PB6/PB7，重映射，115200 8N1）；机器人主控链路保持在 **USART2**（PA2/PA3，**460800**，已由 CubeMX 生成），两条链路各自独占一个 HAL 句柄、互不干扰。

接入后，每个遥测帧到达即刷新“最新角度 / 角速度 / 帧序号”快照，任何任务可无锁读取；模块上电即主动上报，无需主控触发。上报速率在固件内固化为 **200 Hz** 并带 100 Hz → 50 Hz 自动回退，配置结果用 **查询命令直接回读 + 实测帧率**双重确认。串口出错时自动复位解析状态并重挂接收，陀螺仪掉线或接线错误不会拖死主控链路。

## User Stories

1. As 机器人主控开发者, I want 陀螺仪积分角度进入上报数据, so that 我能在上位机做航向闭环而不用额外拉一根线
2. As 机器人主控开发者, I want 角速度（度/秒）一并上报, so that 我能做零速检测与静止判定
3. As 机器人主控开发者, I want 每帧带递增序号, so that 我能检测丢帧而不是把旧数据当新数据用
4. As 机器人主控开发者, I want 陀螺仪数据是“最新值快照”语义, so that 我读的时候不会阻塞接收中断
5. As 固件开发者, I want 陀螺仪初始化在 USART1 初始化之后、调度器启动之前完成一次, so that 上电即开始接收且没有竞态
6. As 固件开发者, I want 上报速率固化在固件里, so that 掉电重启后行为一致
7. As 固件开发者, I want 速率设置失败时自动降级（200→100→50 Hz）, so that 老版本模块固件也能跑起来
8. As 固件开发者, I want 速率是否真正生效可被观测（命令回读 + 实测帧率）, so that 我不必猜“命令发了但模块没理我”
9. As 固件开发者, I want 频率参数按协议字节直接打包下发（不经任何带范围校验的封装）, so that 100/200 Hz 在参考代码的频率枚举只覆盖到 `0x03` 时依然可下发
10. As 固件开发者, I want ACK 不污染“最新遥测”数据, so that 读角度时不会读到 ACK 的残留字段
11. As 固件开发者, I want 串口出错后自动恢复接收, so that 一次噪声不会让陀螺仪永久静默
12. As 固件开发者, I want 半帧/粘包/坏 CRC/噪声字节都被协议层吸收, so that 上层拿到的永远是完整帧
13. As 固件开发者, I want 一个能在 PC 上零依赖编译的协议层, so that 我能在没有硬件的情况下验证帧解析与打包
14. As 固件开发者, I want 新增源文件同时进我在用的构建系统, so that 不会出现“文件写了但没编译”的假成功
15. As 固件开发者, I want 不新增 FreeRTOS 任务就能拿到数据, so that 现有 3 KB 堆与步进计数的实时性不受影响
16. As 固件开发者, I want 每一处自研实现都对应一条“我的 CubeMX 生成事实”，并留下与厂商参考假设的差异记录, so that 第三方例程的假设不会悄悄带进我的工程
17. As 固件开发者, I want 两条串口链路各自独占 HAL 句柄与回调分发, so that 陀螺仪与主控链路不会互踩接收状态
18. As 硬件工程师, I want 陀螺仪接口模式选择脚保持悬空/上拉（串口模式）, so that 模块不会被我误切到 I2C
19. As 硬件工程师, I want 明确知道 PA0/PA8/PB6/PB7 已被占用, so that 我不会把陀螺仪选择脚或信号线接到上面
20. As 运维者, I want 接收帧计数可被直接观察, so that 我能在 30 秒内判定链路是通是断
21. As 运维者, I want 陀螺仪故障不干扰步进计数与主控链路, so that 单点故障不会让整机失控
22. As 项目维护者, I want 过时协议文档被标注、新版被归档, so that 下一个人不会拿旧一代频率表写代码

## Implementation Decisions

**基准原则（本 spec 的最高约束）**
- 本工程 CubeMX 生成物是**唯一事实来源**。厂商代码视为**只读的协议参考**：不复制进本工程、不修改其任何字节；其例程自带的串口假设、printf 重定向、引脚分配、初始化说明一律不作为依据。所有实现必须落在本工程自己的文件里。

**工程侧现状核查（已完成，作为实现输入）**
- 已核实**无需改动**：CubeMX 侧对陀螺仪口本身**零改动**——`__HAL_AFIO_REMAP_USART1_ENABLE()` 已生成（`Core/Src/usart.c:116`），USART1 = PB6/PB7 重映射 / 115200 / NVIC 优先级 5 全部就绪；全局 MSP 初始化已使能 AFIO 时钟（重映射真正生效的前提）；USART1 中断服务程序已生成并指向本工程的 `huart1`；UART/TIM/DMA 三个 HAL 模块均已使能（所需串口 API 全部可链接）；UART NVIC 优先级恰好等于 FreeRTOS 系统调用门限（合法，且我们的中断服务程序内不调用任何 FreeRTOS API，因此连边界风险都不存在）；HAL 时基为定时器（调度器启动前即可用超时发送命令）；两个串口初始化函数之后、调度器启动之前正好存在唯一的插入点（`Core/Src/main.c:97-99`）；工程内不存在任何 printf 重定向，无重复符号；陀螺仪所用引脚与既有功能引脚零冲突。
- 本工程需**新增**（自研实现；厂商源文件零复制、零修改）：
  1. 协议层：纯 C，只依赖 `stdint.h` / `string.h` —— CRC-16/MODBUS、16 B 遥测帧解码、8 B ACK 解码、8 B 命令打包、字节流解析状态机（半帧跨调用拼接、粘包、噪声字节、坏 CRC 后自愈）。
  2. 访问层：绑定 `huart1`、**单字节中断接收 + 每字节重挂**、按句柄分发的收发回调、角度/角速度/序号快照读取、速率协商与查询回读。
  3. 接入点：`Core/Src/main.c` 的 `USER CODE BEGIN 2`（L97-99）内初始化一次；HAL 接收完成回调落在 `USER CODE BEGIN 4`（L160-162）——两处都是 CubeMX 预留的空区，可直接写且不会被重新生成覆盖。
  4. 构建：新增源文件与头文件搜索路径挂进 Keil 与 EIDE 两套配置（当前两套都不含任何陀螺仪目录）。
- 厂商参考代码中“模块接 USART2 / 在 USART2 初始化后调用”的注释**不作为依据**（它对应另一个工程）：本工程实际使用 USART1，接口模式选择脚与引脚分配也另见「硬件约束」。

**模块划分**
- 两层，均在**本工程内自研**：协议层（纯 C，只依赖 `stdint.h` / `string.h`，可在 PC 上零依赖编译与单测）／访问层（依赖 HAL 串口类型：句柄绑定、中断收发、回调分发、快照读取、速率协商）。厂商代码只作协议行为参考，不进入本工程；因此不存在“vendor 补丁维护”负担。

**链路隔离**
- 陀螺仪必须绑定 USART1，主控链路独占 USART2。回调分发须按句柄区分：只有陀螺仪句柄的事件才进入陀螺仪驱动，其余不碰。两条链路不得共享任何 HAL 句柄或收发缓冲。

**调试输出**
- 不引入任何 printf 重定向；调试观察走“接收帧计数”与快照读取，不占用 USART1 / USART2 中任何一个。（厂商参考代码里的 printf 重定向引用本工程不存在的句柄，**不复制进本工程**，该编译错误自然不存在。）

**初始化时序**
- 接入层初始化在 USART1 初始化之后、FreeRTOS 调度器启动之前调用一次（`Core/Src/main.c:97-99`，即 `USER CODE BEGIN 2` 区）；接收采用**单字节中断 + 每字节重挂**。

**时钟与波特率前提（由 CubeMX 生成）**
- 时钟树保持 HSE 8 MHz + PLL×9 → SYSCLK 72 MHz、APB1 36 MHz、APB2 72 MHz。
- 陀螺仪口（USART1，APB2 72 MHz）115200：BRR 应为 `0x271`，测算**除尽、误差 0.000%**。
- 主控口（USART2，APB1 36 MHz）460800：BRR 应为 `0x4E`，实测 461538.46，**误差 0.000%**。✅ **已核实生效**：`Core/Src/usart.c:72` 现为 `460800`，CubeMX 重新生成已完成（该文件 diff 仅此一行）。对端机器人主控必须使用 **8 MHz HSE**（不可沿用其 SDK 样例的 HSI 配置），否则两端不可能同频。
- 若上述时钟树被改动，0.000% 的结论随之失效，必须重算。

**速率设置命令必须绕开枚举**
- 本工程自研命令打包，不经任何带参数范围校验的封装：按协议字节直接拼 **`Cmd=0x03`** + 参数。厂商参考代码的频率枚举只到 `0x03`（比两份文档都旧一代）⇒ **不参考其枚举**。
- 参数取值以 `docs/CY-Z协议.md`（2026-09-11 版）为准：`0x00`=50 Hz、`0x01`=20 Hz、`0x02`=10 Hz、`0x03`=询问模式（不主动上报）、`0x04`=100 Hz、`0x05`=200 Hz。
- ⚠️ **`0x03` 静默陷阱**：它是**合法**取值，但一旦被下发，模块会**完全静默**——“接收帧计数不再增长”的现象与断线/接线错误**无法区分**。因此本工程的速率协商路径**只使用 `0x00`/`0x04`/`0x05`**；`0x03` 仅作协议事实记录，不进入任何下发路径（打包断言见 Testing Decisions）。

**速率协商与直接回读（双重确认）**
- 上电先下发 `Cmd=0x03, Param=0x05`(200 Hz)；ACK 判定为“命令或参数错误”则降 `0x04`(100 Hz)，再失败降 `0x00`(50 Hz)。最终档位必须记录。
- **主确认通道**：下发后用 **`Cmd=0x02, Param=0x00`（查询当前上报频率）回读**，该 ACK 的 `Result` 字段**就是频率码本身**（`0x00`=50 Hz / `0x04`=100 Hz / `0x05`=200 Hz）。这是最直接的生效证据，优于任何间接推断。
- **次确认通道**：实测帧率（1 秒内的接收帧计数）与目标档位吻合。
- ⚠️ **语义陷阱（必须体现在代码里）**：ACK 的 `Result` 含义**随 `Cmd` 而变**——`Cmd=0x02` 时它是**频率码**；其余命令时它是**状态码**（`0x00`=成功、`0x01`=设备未静止、`0x02`=命令或参数错误、`0x03`=执行失败）。同一个 `0x00` 在两种语境下分别是“50 Hz”和“成功”，判定**必须结合 `Cmd` 一起看**，禁止只看 `Result` 数值。

**ACK 与遥测分离**
- ACK 只更新“最近通用帧”，**不更新**“最新遥测”。速率配置与查询结果必须通过**帧回调**捕获；回调在接收解析上下文中执行，禁止在其中做阻塞调用。
- 由于 `Result` 语义随 `Cmd` 变化，回调须同时传出 `Cmd` 与 `Result`，由上层按命令类型解释。

**不使用升级接口**
- 协议层解析缓冲仅 16 字节，而升级命令帧最大 271 字节 ⇒ 固件升级在本架构下不可用，任何 `*_Boot*` 接口都不调用。

**实时性约束**
- 115200 下单字节间隔 **86.8 µs**。任何屏蔽陀螺仪串口中断超过 87 µs 的临界区都会造成溢出丢字节 ⇒ 严禁长临界区；也正因如此，错误回调必须复位解析状态而不能只记错。
- 200 Hz × 16 B ≈ 28% 带宽占用、约 3200 次/秒中断 ≈ 0.3~0.6% CPU，余量充足。

**中断 vs DMA**
- 以当前 CubeMX 事实为准：**未配置任何 DMA 通道**，故按中断实现。是否 DMA 化留待主控链路实测需求确认后另议（Out of Scope）。

**中断优先级**
- 两路串口中断优先级必须 ≥ FreeRTOS 系统调用门限（本工程为 5）。当前配置恰好为 5，合法可用；改动前必须重算。若日后在中断服务程序内新增 FreeRTOS 调用，该优先级即成为硬边界。

**资源**
- 不新增任务/队列，数据通过快照读取。因此当前 3072 字节的 FreeRTOS 堆无需调整；若日后确需新增任务或队列，必须先上调堆（芯片有 20 KB RAM，有余量）。

**硬件约束**
- 陀螺仪接口模式选择脚必须**悬空或上拉**（= 串口模式），**严禁接地**（会切到 I2C）。模块内部已上拉。**（已确认实物为悬空 → 串口模式。）**
- 本工程 PA0 已被 TIM2_CH1 外部计数占用、PA8 已被 TIM1_CH1 占用、**PB6/PB7 已用于 USART1 重映射** ⇒ 禁止沿用厂商 F103 例程的引脚分配（例程用 I2C1 = PB6/PB7 + 选择脚 PA0，与本工程正面冲突）。

**构建**
- Keil 与 EIDE 两套工程配置都存在。新增源文件与头文件搜索路径必须挂进实际使用的那一套（建议两套都挂以免切换时踩空），否则出现“文件写了但没编译”的假成功。

## Testing Decisions

- **好测试的定义**：只验证外部行为——给定字节流，断言输出的帧类型/字段/状态码。不测内部状态机变量、不测私有函数、不依赖帧在缓冲里的偏移。
- **唯一 seam**：**本工程自研协议层**。理由：它是全工程唯一“既能承载真实协议逻辑、又能在 PC 上零依赖编译”的边界（只依赖 `stdint.h` / `string.h`）。它之上的一切——中断、HAL、FreeRTOS、任务时序——不做单元测试，改由硬件在环验收覆盖。**不新增任何 seam。**
- **该 seam 上的覆盖项**：
  - 遥测帧：字段解码（序号/角度/角速度）、长度错误、帧尾错误、CRC 错误
  - ACK：`Cmd=0x02`（Result 为频率码）与其余 `Cmd`（Result 为状态码）两条语义分支必须分别断言，防止混用
  - 命令打包：`Cmd=0x03` 携带参数 `0x00`/`0x04`/`0x05` 的字节级正确性；非法参数不崩溃
  - 流式注入口：半帧跨调用拼接、两帧粘连、帧间噪声字节、坏 CRC 后**自愈**（后续好帧仍能解出）
- **prior art**：厂商示例本身即“协议层与 HAL 分离”的设计，并在注释里示范了“喂字节 → 看接收帧计数”的调试法。我们**沿用其分层思路与调试手法，但按本工程事实重新实现**，不复制其代码。
- **硬件在环验收（非自动化，作为出关条件）**：
  1. 接上模块后接收帧计数持续递增 = 链路通（默认应 ≈50 帧/秒）
  2. 下发 200 Hz 后，查询命令回读得到 `0x05` **且** 1 秒实测帧率 ≈200、帧间隔 ≈5 ms = 速率真生效
  3. 拔掉模块 TX：接收帧计数停止增长，但**步进计数与主控链路不受影响** = 故障隔离成立

## Out of Scope

- 陀螺仪固件升级 / Bootloader：协议层解析缓冲仅 16 字节，架构上不支持
- 比例因子校准流程的自动化：需人工按 1/2/3/6 圈旋转，只在需要时手动触发
- **上报帧的负载布局**：帧长 46 字节的说法尚未在任何一方证据中确认——厂商定义的响应帧只有 16 B 遥测（`AA 55`）、8 B ACK（`A5 5B`）、12 B 比例因子响应（`A5 5C`）与 8 B 命令（`A5 5A`）。并入主控上报帧的字段排布待主控侧协议确定后另开 spec；本 spec 只负责把角度/角速度/序号做成可读快照
- 主控链路（USART2）的收发实现与 DMA 化：本 spec 只锁定参数 **460800（由 CubeMX 生成）**与对端必须使用 8 MHz HSE
- 陀螺仪安装机械误差、外参标定、与零位开关的融合策略

**其他已核实事实**
- 模块 UART：115200 / 8 / N / 1 / 无流控。文档里写的 "USART1" 是笔误（模块只有一路 UART，与宿主挂哪个串口无关）。
- 所有多字节字段 little-endian；CRC-16/MODBUS（初值 `0xFFFF`、多项式 `0xA001`、低字节在前）。
- 四类帧：

  | 方向 | Header | 长度 | 用途 |
  |---|---|---|---|
  | 模块→主机 | `AA 55` | 16 B | 遥测：Seq / AngleDeg(f32) / GyroDps(f32) / CRC / `55 AA` |
  | 模块→主机 | `A5 5B` | 8 B | ACK：Cmd / Result / Seq / CRC / `5B` |
  | 模块→主机 | `A5 5C` | 12 B | 比例因子响应：Cmd / Seq / GyroScaleFactor(f32) / Reserved / CRC / `5C` |
  | 主机→模块 | `A5 5A` | 8 B | 命令：Cmd / Param / Seq / CRC / `5A` |

- 接口模式选择脚：高电平或悬空 = 串口（默认）；接 GND = I2C。切换电平后模块自动改用对应接口。
- 厂商 `.c` 注释是 UTF-8 无 BOM 中文，Keil 默认 GBK 会显示乱码（不影响编译）。
